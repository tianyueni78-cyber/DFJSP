# 知识地图工作表

## 当前总目标

用这篇 FJSP-AGV 论文代码作为样本，建立一套自己能看懂、后期能复现、以后能迁移到相近智能调度论文的知识地图。

这不是为了展示，也不是为了堆文档。每个模块都要服务三个问题：

1. 我能不能看懂这套代码在干什么？
2. 我以后能不能复现或排查问题？
3. 我换一篇智能调度论文时，能不能复用这套理解方法？

## 工作节奏

采用“两轮走”：

```text
第一轮：先把完整骨架跑通
第二轮：根据真实卡点回头细化
```

第一轮不追求完美，目标是每个关键模块都有第一版。  
第二轮再补变量例子、流程细节、复现步骤和封装方案。

## 第一轮完成标准

第一轮完成时，至少应该能回答：

- 这个项目研究什么调度问题？
- 数据从哪里来，进入哪些变量？
- 一个调度方案为什么能表示成染色体？
- `sorting.m` 为什么是核心解码器？
- `fitness.m` 为什么决定方案好坏？
- 算法为什么是在搜索染色体，而不是直接操作工厂？
- 一键运行脚本到底做了哪些实验，输出了哪些图和指标？
- 以后要封装和复现，最容易出错的点在哪里？

## 当前优先级

下一步建议做：

```text
模块 8：复现与封装路线
```

原因：

- 第一轮的系统理解骨架已经基本打通。
- 现在需要把“看懂”转成“以后怎么稳妥拆分和复现”。
- 这直接关系到后续封装代码时少报错、少返工。

建议新增：

```text
docs/08_engineering/refactor_roadmap.md
```

重点分析：

- 哪些模块应该先封装。
- 哪些数据读取必须先纯函数化。
- 如何建立最小稳定链路：数据读取 -> 单个染色体评价。
- 哪些地方最容易报错。
- 哪些内容暂时不该动。

## 第二轮可能回头细化的内容

第一轮完成后，不继续盲目扩文档，而是根据你最卡的地方回头加深。

| 卡点 | 回头细化方向 |
|---|---|
| 看不懂 `OS / MS / AS / SS` | 补染色体小例子 |
| 看不懂 `sorting.m` | 补 `curJob`、`jobOpera`、`machineTable`、`AGVTable` 变量流向 |
| 看不懂 `fitness.m` | 补机器能耗、AGV 能耗、空闲能耗计算例子 |
| 不知道一键运行发生什么 | 补 `dif_main.m` 执行顺序 |
| 想开始封装代码 | 补最小稳定链路：数据读取 -> 单个染色体评价 |
| 想理解算法改进 | 分别分析 VNS、Q-learning、反向学习，不混在基础搜索里 |

## 每次任务的汇报格式

以后每次完成任务，都按这个格式汇报：

```text
本次做的是第 X 个模块：xxx
状态：第一版完成 / 更新完成 / 还缺什么
新增或更新了哪些文件
是否提交 GitHub
下一步建议做哪个模块
```

这样可以避免一边做一边跑偏。
