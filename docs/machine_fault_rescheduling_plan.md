# FJSP-AGV 机器故障动态重调度实施计划

## 1. 项目目标

在现有 FJSP-AGV 调度代码和现有数据基础上，建立支持一个或多个机器故障事件的动态重调度程序。

程序需要实现：

1. 基于事件驱动的机器故障响应。
2. 二叉树部分右移重调度。
3. 基于未开工工序的完全重调度。
4. 根据综合评价指标自动选择最终方案。
5. 单机器故障、多个机器同时故障和连续故障。

单机器故障仅作为第一个验证场景，不是程序最终能力边界。

## 2. 调度思维

本项目同时采用局部调整和全局优化两种思维。

### 2.1 二叉树部分右移重调度

二叉树右移属于局部修复策略：

- 保持原机器分配和未受影响计划不变。
- 从故障影响工序开始传播延迟。
- 左分支表示同一工件的后续工序。
- 右分支表示同一机器上的后续工序。
- 只移动因前序约束或机器占用冲突而受影响的工序。

### 2.2 完全重调度

完全重调度属于剩余任务全局优化策略：

- 冻结故障时刻以前已完成的工序。
- 保留正常机器上正在加工的工序，直到其原计划完成。
- 对故障后尚未开工的全部工序重新优化。
- 允许重新决定工序顺序、候选机器和相应的 AGV 调度。

这里的“完全”是针对故障后的剩余任务，不推翻已经执行的历史计划。

### 2.3 组合重调度

分别生成部分右移方案和完全重调度方案，并计算：

```text
tD = 重调度后的最大完工时间 - 原计划最大完工时间

SD = 机器分配发生改变的工序数量

Y = omega1 * tD + omega2 * SD
```

最终采用 `Y` 较小的方案。

## 3. 故障事件

单个故障事件包含：

```matlab
fault.machine_id
fault.start_time
fault.repair_duration
fault.repair_end_time
```

多个故障使用结构体数组：

```matlab
faults(1).machine_id = 1;
faults(1).start_time = 50;
faults(1).repair_duration = 20;

faults(2).machine_id = 3;
faults(2).start_time = 70;
faults(2).repair_duration = 15;
```

程序按照故障发生时间依次处理事件，并合并同一机器上相互重叠的不可用区间。

## 4. 约束和假设

1. 零时刻所有机器处于待机状态。
2. 工件的工艺顺序不可改变，工序先后关系不可逆。
3. 故障机器上的直接受影响工序停止加工。
4. 其他正常机器上正在加工的工序继续加工到完成。
5. 故障机器可以恢复，恢复时间可预测。
6. 每台机器同一时刻只能加工一道工序。
7. 每个工件同一时刻只能在一台机器上加工。
8. 工序加工时间包含加工时间和相关准备时间。
9. 已经完成的加工和运输任务冻结。
10. 故障机器在不可用区间内不得加工。
11. 每道需要完成的工序在最终计划中恰好出现一次。

## 5. AGV 联动边界

原代码中的 AGV 调度规则保持不变：

- 同一辆 AGV 同一时刻只能执行一个任务。
- 保持原空载和负载运输时间算法。
- 保持速度档位编码。
- 保持电量消耗、充电阈值和充电策略。
- 工件到达目标机器后才能开始加工。
- 最后一道工序完成后仍需运送到卸载站。

机器故障重调度只改变必要的加工开始时间或机器分配。发生变化后，复用原调度逻辑重新生成相关 AGV 运输，保证：

- 目标机器变化时运输路线同步变化。
- 工序开始时间不早于负载运输到达时间。
- AGV 任务之间不存在时间冲突。

## 6. 总工作流程

```text
生成正常调度方案
→ 输入一个或多个机器故障事件
→ 按时间排序并合并同时发生的事件
→ 提取故障时刻系统状态
→ 冻结已完成工序和正常机器在制工序
→ 标记故障机器及其受影响工序
→ 生成二叉树部分右移方案
→ 生成未开工工序完全重调度方案
→ 按原规则重新计算受影响的 AGV 运输
→ 检查两个候选方案的可行性
→ 计算 tD、SD 和 Y
→ 选择 Y 较小的最终方案
→ 输出指标对比和甘特图
```

## 7. 分阶段工作表

| 阶段 | 阶段目标 | 主要工作 | 完成标准 |
|---|---|---|---|
| 1 | 建立正常调度基线 | 整理原代码最小运行入口，读取现有数据，生成正常计划 | 输出染色体、机器时间表、AGV 时间表和完工时间 |
| 2 | 定义多故障事件 | 建立并校验 `faults[]`，按时间排序，合并重叠区间 | 支持单故障、同时故障和连续故障输入 |
| 3 | 提取事件时刻状态 | 分类已完成、正常在制、故障在制和未开工工序 | 每道工序恰好属于一个状态 |
| 4 | 建立机器不可用约束 | 为每台故障机器生成不可用时间区间 | 不可用区间内不存在加工块 |
| 5 | 实现部分右移 | 构建工件后继和机器后继影响传播树，更新受影响时间 | 未受影响工序保持不变，受影响工序无冲突 |
| 6 | 实现完全重调度 | 冻结历史，对未开工工序重新编码和优化 | 所有剩余工序全部且仅调度一次 |
| 7 | 实现 AGV 联动 | 复用原运输、速度、电量和充电逻辑重建相关运输 | 加工不得早于运输到达，AGV 无时间冲突 |
| 8 | 实现评价指标 | 计算 `tD`、`SD` 和 `Y` | 指标与手工小算例一致 |
| 9 | 实现组合选择 | 比较右移和完全重调度方案 | 自动返回 `Y` 较小的可行方案 |
| 10 | 验证故障场景 | 验证单故障、同时故障和连续故障 | 三类场景都能生成可行计划和指标对比 |

## 8. 可行性验收条件

每个候选方案和最终方案必须满足：

1. 无机器加工时间重叠。
2. 无 AGV 任务时间重叠。
3. 无工序先后关系冲突。
4. 无故障区间加工。
5. 工序开始时间不早于工件运输到达时间。
6. 所有应完成工序恰好调度一次。
7. 已冻结工序的计划不被修改。
8. 输出原计划、部分右移方案、完全重调度方案和最终方案的指标。
