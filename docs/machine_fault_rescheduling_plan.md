## 1. 项目目标

在现有 FJSP-AGV 调度代码和现有数据基础上，建立支持一个或多个机器故障事件的动态重调度程序。

程序需要实现：

1. 基于事件驱动的机器故障响应。
2. 二叉树部分右移重调度。
3. 基于未开工工序的完全重调度。
4. 根据综合评价指标自动选择最终方案。
5. 单机器故障、多个机器同时故障和连续故障。

单机器故障仅作为第一个验证场景，不是程序最终能力边界。

## 2. 调度思维

本项目同时采用局部调整和全局优化两种思维。

### 2.1 二叉树部分右移重调度

二叉树右移属于局部修复策略：

- 保持原机器分配和未受影响计划不变。
- 从故障影响工序开始传播延迟。
- 左分支表示同一工件的后续工序。
- 右分支表示同一机器上的后续工序。
- 只移动因前序约束或机器占用冲突而受影响的工序。

### 2.2 完全重调度

完全重调度属于剩余任务全局优化策略：

- 冻结故障时刻以前已完成的工序。
- 保留正常机器上正在加工的工序，直到其原计划完成。
- 对故障后尚未开工的全部工序重新优化。
- 允许重新决定工序顺序、候选机器和相应的 AGV 调度。

这里的“完全”是针对故障后的剩余任务，不推翻已经执行的历史计划。

### 2.3 组合重调度

分别生成部分右移方案和完全重调度方案，并计算：

```text
tD = 重调度后的最大完工时间 - 原计划最大完工时间

SD = 机器分配发生改变的工序数量

Y = omega1 * tD + omega2 * SD
```

最终采用 `Y` 较小的方案。

## 3. 故障事件

单个故障事件包含：

```matlab
fault.machine_id
fault.start_time
fault.repair_duration
fault.repair_end_time
```

多个故障使用结构体数组：

```matlab
faults(1).machine_id = 1;
faults(1).start_time = 50;
faults(1).repair_duration = 20;

faults(2).machine_id = 3;
faults(2).start_time = 70;
faults(2).repair_duration = 15;
```

程序按照故障发生时间依次处理事件，并合并同一机器上相互重叠的不可用区间。

## 4. 约束和假设

1. 零时刻所有机器处于待机状态。
2. 工件的工艺顺序不可改变，工序先后关系不可逆。
3. 故障机器上的直接受影响工序停止加工。
4. 其他正常机器上正在加工的工序继续加工到完成。
5. 故障机器可以恢复，恢复时间可预测。
6. 每台机器同一时刻只能加工一道工序。
7. 每个工件同一时刻只能在一台机器上加工。
8. 工序加工时间包含加工时间和相关准备时间。
9. 已经完成的加工和运输任务冻结。
10. 故障机器在不可用区间内不得加工。
11. 每道需要完成的工序在最终计划中恰好出现一次。

## 5. AGV 联动边界

原代码中的 AGV 调度规则保持不变：

- 同一辆 AGV 同一时刻只能执行一个任务。
- 保持原空载和负载运输时间算法。
- 保持速度档位编码。
- 保持电量消耗、充电阈值和充电策略。
- 工件到达目标机器后才能开始加工。
- 最后一道工序完成后仍需运送到卸载站。

机器故障重调度只改变必要的加工开始时间或机器分配。发生变化后，复用原调度逻辑重新生成相关 AGV 运输，保证：

- 目标机器变化时运输路线同步变化。
- 工序开始时间不早于负载运输到达时间。
- AGV 任务之间不存在时间冲突。

## 6. 总体推进结构

项目采用“两层计划”：

1. **研究阶段**回答“先研究哪一类机器故障，再扩展到哪一类故障”。
2. **技术工作包**回答“为了完成每个研究阶段，需要实现哪些代码模块”。

研究阶段按 A、B、C 顺序推进。技术工作包可以被多个研究阶段复用，但每次只实施当前研究阶段所需的最小范围。

## 7. 三个研究阶段

### 7.1 阶段 A：单机器在工序完成时发生故障

**研究目标：**

先复现论文的基本场景，建立并验证机器故障动态重调度主流程。故障时刻设置在某道工序刚完成之后，因此暂时不存在加工中工序的剩余加工时间问题。

**阶段内工作步骤：**

1. 建立故障前的正常机器与 AGV 调度基线。
2. 定义单个机器故障事件。
3. 将故障时刻限制为某道工序的完成时刻。
4. 提取故障时刻已完成工序、已完成运输和未开始任务。
5. 设置故障机器维修不可用区间。
6. 实现二叉树部分右移重调度。
7. 实现基于未开工工序的完全重调度。
8. 按原项目规则重新生成受影响的 AGV 运输。
9. 计算 `tD`、`SD` 和 `Y`。
10. 在右移方案和完全重调度方案之间进行组合选择。
11. 使用单机器故障小场景检查全部约束。

**完成标准：**

- 能从同一正常计划生成右移方案和完全重调度方案。
- 两个候选方案均通过机器、工序和 AGV 约束检查。
- 能输出两个方案的分项指标及最终选择结果。
- 不涉及在制工序从头加工或续加工的规则。

**最终状态：已完成并收口。**

- 正常基线、故障事件、状态快照、影响传播均已验证；
- 部分右移、AGV 联动、完全重调度和组合选择均已实现；
- 约束、能耗、权重敏感性和多随机种子实验均已完成；
- 最终成果见[阶段 A 最终总结](stage_a_final_summary.md)。

### 7.2 阶段 B：单机器在加工过程中发生故障

**研究目标：**

解决论文算例避开的在制工序中断问题，使程序能够处理任意加工时刻发生的单机器故障。

**当前状态：第 1 步测试已通过；第 2 步已确定第一版采用“暂停加工、保留
进度、修复后在原机器续加工”，代码和文档已完成静态实现，MATLAB 轻量
测试待执行。暂不修改搜索算法。**

**阶段内工作步骤：**

1. 识别故障时正在故障机器上加工的工序。
2. 记录该工序的原加工时间、已加工时间和剩余加工时间。
3. 实现第一版“暂停加工、保留进度、修复后在原机器续加工”规则。
4. 将故障区间加入机器不可用时间窗。
5. 更新中断工序的完成时间。
6. 沿工件后继、机器后继和 AGV 运输约束传播时间影响。
7. 重新生成部分右移和完全重调度候选方案。
8. 检查修复后机器重新参与调度的行为。
9. 增加加工中故障的状态与约束测试。
10. 必要时再把“从头加工”或“允许转移机器”作为对比规则，而不是第一版默认规则。

第 2 步详细记录：

**完成标准：**

- 能正确计算故障时在制工序的剩余加工时间。
- 故障机器在维修区间内没有加工任务。

### 7.3 阶段 C：多机器故障

**研究目标：**

在单机器故障逻辑稳定后，扩展到多台机器同时故障和多个故障连续发生。

**阶段内工作步骤：**

1. 使用统一的 `faults[]` 表达全部故障事件。
2. 按故障发生时间排序事件。
3. 合并同一机器上重叠的不可用区间。
4. 支持多台机器在同一时刻发生故障。
5. 分别建立各故障的直接影响集合。
6. 合并并去重多个影响传播集合。
7. 处理同一工序同时受到多个故障传播影响的情况。
8. 支持在新计划执行过程中继续发生故障。
9. 每次连续故障发生后重新提取当时的系统状态。
10. 重新生成局部方案、完全重调度方案和 AGV 调度。
11. 验证同时故障和连续故障场景。

**完成标准：**

- 同一输入接口可表达单故障、同时故障和连续故障。
- 多个影响集合合并后没有重复调度或遗漏工序。
- 每次故障事件后都能从当前执行状态继续重调度。
- 多故障场景满足与单故障相同的可行性约束。

## 8. 每个研究阶段的共同技术流程

```text
定义当前研究场景
→ 生成或读取正常调度基线
→ 输入当前阶段允许的故障事件
→ 提取故障时刻系统状态
→ 冻结已完成和当前规则规定不可改变的任务
→ 标记故障机器及其受影响工序
→ 生成二叉树部分右移方案
→ 生成未开工工序完全重调度方案
→ 按原规则重新计算受影响的 AGV 运输
→ 检查两个候选方案的可行性
→ 计算 tD、SD 和 Y
→ 选择 Y 较小的最终方案
→ 验证约束并记录结果
```

阶段 A、B、C 都使用这条流程，但“故障事件类型”“冻结范围”和“在制工序处理规则”会随研究阶段逐步扩展。

## 10. 可行性验收条件

每个候选方案和最终方案必须满足：

1. 无机器加工时间重叠。
2. 无 AGV 任务时间重叠。
3. 无工序先后关系冲突。
4. 无故障区间加工。
5. 工序开始时间不早于工件运输到达时间。
6. 所有应完成工序恰好调度一次。
7. 已冻结工序的计划不被修改。
8. 输出原计划、部分右移方案、完全重调度方案和最终方案的指标。
