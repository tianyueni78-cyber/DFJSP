# 阶段 A 第 10 步：同等预算正常调度基线搜索

## 1. 数据来源

本步骤只使用原项目：

- `Mk02.fjs` 工件、工序、候选机器和加工时间；
- 原机器数据；
- 原 AGV 数据；
- 原 `OS/MS/AS/SS` 编码；
- 原正常调度解码与能耗计算。

不会生成新工件、新机器、新加工时间、新运输距离或替代数据。搜索产生的是原数据可行域中的候选调度方案。

用户已明确允许：基于上述原数据生成优化候选方案。该授权不包括修改
`raw_code/`、替换原实例或自行构造另一组问题数据。

## 2. 目的

原故障前基线只是一条随机染色体，而故障后完全重调度经过自适应 NSGA-II 搜索，二者优化预算不公平。

本步骤为正常调度增加同等预算搜索：

- 种群 `10`；
- 最大 `100` 代；
- 交叉概率 `0.8`；
- 变异概率 `0.2`；
- 连续 `10` 代无 Pareto 改善停止；
- 最长 `30` 秒；
- 随机种子 `42`。

## 3. 目标

正常搜索仍使用原项目双目标：

```text
makespan
total_energy
```

Pareto 前沿按两个目标值去重。

## 4. 基线选择

第一版从正常 Pareto 前沿中选择：

1. 完工时间最小；
2. 完工时间并列时总能耗最小。

全部 Pareto 候选仍保留，后续可以开展基线选择敏感性分析。

## 5. 公平比较流程

```text
原数据
→ 同等预算优化正常基线
→ 在选定优化基线上重新定位 J5-O1 完成时故障
→ 重新检查 tr=5 是否产生有效影响
→ 从该优化基线生成右移和完全重调度方案
→ 重新计算 tD、SD、Y
```

不能继续使用旧随机基线的绝对故障时刻。

## 8. 结论修正

原组合评价将故障后优化方案与完工时间 `144.2033` 的随机正常计划比较，
得到 `tD=-44.23`。现在同等预算正常搜索已将正常基线优化到 `112.72`，
因此旧负偏差主要混入了正常计划优化收益，不能解释为故障重调度收益。

旧组合结果保留为程序调试记录，但正式研究结论必须在新优化基线上重新计算。
