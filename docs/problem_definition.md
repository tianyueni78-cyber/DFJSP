# 问题定义

## 第一阶段研究边界

第一阶段假设故障事件已经由外部设备、PLC、MES 或人工报告检测完成。本项目只研究收到故障事件后的动态重调度，不研究传感器故障诊断。

本项目最终需要支持一个或多个机器故障事件，包括：

1. 单机器故障，用于验证基本重调度方法。
2. 多台机器同时故障。
3. 多个机器故障连续发生。

单机器故障只是第一个测试场景，不是程序最终能力边界。

## 当前基本假设

1. 故障开始时刻和预计维修时长已知。
2. 故障期间，故障机器不可执行新工序。
3. 故障前已经完成的工序和运输任务保持不变。
4. 未受故障影响且正在加工的工序继续加工至完成。
5. 工件的工艺顺序不能改变。
6. 每个工件在同一时刻只能由一台机器加工。
7. 尚未开始的工序可在完全重调度中重新选择候选机器。
8. 故障机器可以修复。
9. AGV 不发生故障，但机器或工序时间变化后必须重新检查 AGV 运输约束。
10. 暂不同时考虑新订单、订单取消和加工时间随机变化。

故障时正在故障机器上加工的工序如何处理，论文没有完全说明，当前仍属于需要明确的项目规则，不能直接写成论文结论。

## 问题来源

在把论文中的机器故障重调度方法迁移到现有 FJSP-AGV 代码前，需要把论文中的文字描述转化为可编程规则。因此提出了以下问题：

1. 正在加工的工序是否必须从头加工？
2. 故障机器修复后是否重新参与调度？
3. 局部修复允许调整多大范围？
4. 计划扰动采用开始时间变化、机器变化，还是加权组合计算？

本节答案来自论文《基于随机机器故障的柔性作业车间动态调度》的问题假设、重调度评价指标、右移重调度、完全重调度和仿真分析部分。

## 已查明的问题与依据

### 1. 正在加工的工序是否必须从头加工？

**结论：论文没有明确规定。**

论文在问题假设中规定：

- 故障机器上直接受到影响的工序停止加工；
- 其他机器上未受到影响且正在加工的工序继续加工至完成；
- 故障机器可恢复，恢复时间可预测。

但是论文没有继续说明故障机器上的中断工序在恢复后应当：

- 保留已完成进度并继续加工；
- 放弃已完成进度并从头加工；
- 转移到另一台候选机器重新加工。

论文右移重调度算例又采用“工序 `O21` 加工完成时机器 `M1` 故障”的场景，实际上避开了加工中断后的剩余加工时间问题。因此，不能根据该论文得出“必须从头加工”的结论。

**依据位置：**

- 论文第 649 页，问题描述中的假设③和假设④；
- 论文第 652 页，右移重调度算例说明。

### 2. 故障机器修复后是否重新参与调度？

**结论：论文含义上是重新参与生产，但没有详细规定重新加入调度的具体时点。**

论文明确假设机器故障后可恢复且恢复时间可预测。仿真部分也将维修结束描述为“恢复正常工作状态”。右移方法则按照恢复时间推迟受影响工序，这意味着故障机器在维修区间结束后重新可用。

论文没有进一步区分：

- 修复完成后立即恢复执行原机器队列；
- 修复完成后等待下一次重调度再加入；
- 修复完成后是否允许接受重新分配的其他工序。

**依据位置：**

- 论文第 649 页，假设④；
- 论文第 653 页，仿真场景中的“恢复正常工作状态”；
- 论文第 651 至 652 页，右移重调度公式及说明。

### 3. 局部修复允许调整多大范围？

**结论：论文没有设置固定工序数量或固定时间窗口，而是采用影响传播范围。**

论文的部分右移重调度从故障影响工序 `Oij` 出发：

1. 只考察未开始工序集合 `O'`。
2. 沿同一工件的后续工序传播，形成左子树。
3. 沿同一机器上的后续工序传播，形成右子树。
4. 只有原开始时间早于新的最早可开始时间、产生时间冲突的工序才被加入影响集合。
5. 反复传播，直到不再产生新的受影响工序。

所以局部修复范围由故障造成的时间冲突决定，而不是预先规定“调整后面几道工序”。没有受到传播影响的工序保持原计划。

**依据位置：**

- 论文第 651 至 652 页，式（7）至式（12）及二叉树右移步骤；
- 论文第 653 至 654 页，仿真分析中“只针对部分受影响工序进行右移”的说明。

### 4. 计划扰动如何计算？

**结论：论文采用完工时间偏差与机器分配变化的加权组合，不使用开始时间变化。**

论文定义：

```text
tD = 重调度后的最大完工时间 - 原计划最大完工时间
SD = 加工机器发生变化的工序数量
Y  = ω1 × tD + ω2 × SD
ω1 + ω2 = 1
```

`Y` 越小，方案越好。论文仿真中采用：

```text
ω1 = 0.9
ω2 = 0.1
```

论文虽然把 `SD` 称为序列偏差，但式（4）和式（5）实际统计的是对应工序加工机器是否发生变化，并没有计算工序开始时间变化或机器队列位置变化。

**依据位置：**

- 论文第 651 页，式（3）至式（6）；
- 论文第 653 页，仿真权重设置。

## 论文没有解决的问题

以下问题无法直接从论文中获得完整编程规则：

1. 故障机器上的在制工序是续加工、从头加工，还是允许转移机器？
2. 如果续加工，剩余加工时间如何计算，是否考虑重新准备时间？
3. 如果转移机器，已完成加工量是否能够保留？
4. 故障机器修复后是立即加入当前计划，还是等待下一次重调度事件？
5. 修复后的机器是否允许接受完全重调度重新分配的其他工序？
6. `SD` 应统计全部工序，还是只统计故障时刻后的未完成工序？
7. `tD` 和 `SD` 的量纲不同，是否需要归一化后再加权？
8. 论文权重 `0.9/0.1` 是否直接用于本项目，还是通过敏感性分析确定？
9. 多台机器同时故障时，多个影响传播树如何合并和去重？
10. 连续故障发生时，是否中断当前重调度计算并重新提取系统状态？
11. 已经开始运输的 AGV 任务是否冻结？
12. AGV 正在运往故障机器时，是否允许途中改道？
13. 目标机器变化时，是否重新计算空载和负载运输时间、AGV 冲突及能耗？
14. 重调度算法的计算耗时是否计入生产系统时间？
15. 预计维修时间发生变化时，是否再次触发重调度？

## 当前建议及理由

### 建议 1：第一版采用“暂停后续加工”

故障机器上的在制工序保留故障前已经完成的加工进度；机器修复后，在原机器上完成剩余加工时间。第一版暂不允许该在制工序迁移到其他机器。

**理由：**

- 最接近论文“停止加工”和“机器可恢复”的文字含义；
- 不需要假设已完成加工量全部报废；
- 不引入跨机器迁移、重新装夹和质量损失等论文未提供的数据；
- 适合作为第一版基础规则，后续可以增加“从头加工”和“允许转移”作为对比场景。

### 建议 2：故障机器在维修结束后立即恢复可用

机器在区间 `[故障开始时刻, 维修结束时刻)` 内不可用，维修结束后重新参与调度。

**理由：**

- 与论文“恢复正常工作状态”一致；
- 可以用明确的机器不可用时间窗实现；
- 同时适用于右移重调度和完全重调度。

对于维修结束前已经生成的完整重调度方案，故障机器只能安排开始时间不早于维修结束时刻的工序。

### 建议 3：局部修复采用影响传播闭包

不设置固定调整数量。以直接受故障影响的工序为起点，沿工件工艺约束、机器占用约束以及新增的 AGV 运输约束传播，直到没有新的冲突。

**理由：**

- 保留论文二叉树右移方法的核心思想；
- 比固定窗口更符合实际影响范围；
- 能避免修改没有受到故障影响的工序；
- 可自然扩展到多个同时或连续故障事件。

### 建议 4：第一版保留论文指标，同时记录扩展指标

组合方案选择第一版使用论文指标：

```text
Y = ω1 × tD + ω2 × SD
```

同时额外记录但暂不纳入第一版选择公式：

- 工序开始时间变化总量；
- 被调整工序数量；
- AGV 任务变化数量；
- 重调度算法运行时间。

**理由：**

- 先复现论文的决策逻辑，便于验证实现是否一致；
- 原项目包含 AGV，额外记录运输扰动可以发现论文指标看不到的问题；
- 先记录数据，再决定是否修改目标函数，避免一开始改变过多规则。

### 建议 5：`SD` 只统计可重调度的未完成工序

已完成工序和被冻结任务不能改变，不应进入实际扰动计数。正在执行且按规则冻结机器分配的工序也不应被重复计算。

**理由：**

- 扰动指标应评价重调度决策造成的变化；
- 已完成任务不属于重调度决策空间；
- 可以避免固定历史任务稀释或干扰指标。

### 建议 6：暂用论文权重，但同步输出分项指标

第一版暂用 `ω1 = 0.9`、`ω2 = 0.1`，同时分别输出 `tD`、`SD` 和 `Y`，不只保存总分。

**理由：**

- 便于先按论文方法进行验证；
- 能看出最终选择主要由哪个指标决定；
- 后续可以再做归一化和权重敏感性分析，而不需要修改历史结果含义。

## 当前需要确认的项目规则

在编写机器故障逻辑前，优先确认以下规则：

1. 是否接受“在制工序暂停，修复后在原机器续加工”作为第一版规则？
2. 是否接受故障机器维修结束后立即重新可用？
3. 是否接受局部修复范围由影响传播决定，而不设置固定数量？
4. 第一版是否采用论文的 `Y = 0.9 × tD + 0.1 × SD`？
5. 是否同意第一版禁止故障在制工序跨机器迁移？
6. AGV 已经开始执行的运输任务是否一律冻结，还是目标机器故障时允许改道？

上述规则确认后，才能把论文方法转换成无歧义的程序状态和约束。
