# 阶段 A 第 1 步：建立正常调度基线

## 1. 这一步在整个项目中的位置

当前研究路线是：

```text
阶段 A：工序完成时单机器故障
→ 阶段 B：加工中单机器故障
→ 阶段 C：多机器同时或连续故障
```

本次完成的是：

```text
阶段 A
└── 第 1 步：建立故障发生前的正常机器与 AGV 调度基线
```

对应总体实施计划中的“技术工作包 1：建立正常调度基线”。

## 2. 为什么必须先做这一步

机器故障重调度不是从空白状态重新排产，而是在一份正在执行的正常计划上发生变化。

后续要判断：

- 故障时哪些工序已经完成；
- 哪些工序尚未开始；
- 哪台机器原本安排了哪些工序；
- AGV 原本执行哪些运输任务；
- 故障后最大完工时间增加了多少；
- 重调度后有多少工序更换了机器。

这些判断都需要一份统一的故障前计划作为比较基准。因此，必须先把“正常调度结果”整理成后续故障模块可以直接读取的数据结构。

这一步没有解决机器故障，而是在建立机器故障研究的起点。

## 3. 原代码为什么不能直接作为新入口

原项目主要通过 `raw_code/dif_main.m` 运行。

该文件同时负责：

- 读取 FJSP 算例；
- 读取机器和 AGV Excel 数据；
- 生成染色体；
- 运行 INSGA-II、NSGA-II、MOEA/D、MOSSA 和 MOPSO；
- 计算多个评价指标；
- 绘制图形；
- 切换工作目录；
- 保存和展示实验结果。

它适合执行原论文的完整算法对比实验，但不适合直接作为机器故障项目的基础入口。

机器故障模块只需要得到一份明确的正常计划，不需要每次都运行五种算法、绘图或改变目录。

## 4. 这一步具体做了什么

### 4.1 拆出无副作用的数据读取

新增三个读取函数：

- `src/data/read_fjsp.m`
- `src/data/read_machine_data.m`
- `src/data/read_agv_data.m`

它们分别读取：

- 工件、工序、候选机器和加工时间；
- 机器距离和机器能耗；
- AGV 数量、速度和能耗。

这些函数只返回数据，不生成 `data.mat`，也不修改原 Excel 文件。

### 4.2 建立正常计划包装函数

新增：

- `src/scheduling/build_normal_schedule.m`

它接收一条完整染色体以及模型数据，调用已经迁移的正常调度解码链，返回统一的 `baseline` 结构。

它不负责搜索最优解，也不包含机器故障逻辑。

### 4.3 建立统一运行入口

新增：

- `scripts/run_normal_schedule_baseline.m`

入口执行顺序为：

```text
读取配置
→ 读取 FJSP、机器和 AGV 数据
→ 使用固定随机种子生成一条染色体
→ 调用正常调度包装函数
→ 在内存中返回 baseline
```

当前入口不保存文件、不绘图，也不生成 `outputs`。

### 4.4 建立配置入口

新增：

- `configs/normal_schedule_config.m`

配置中记录：

- 随机种子；
- Mk02 算例位置；
- 机器数据位置；
- AGV 数据位置；
- AGV 最大电量；
- 充电速度。

路径由项目根目录动态组合，没有写死本机盘符。

### 4.5 建立契约测试

新增：

- `tests/test_normal_schedule_contract.m`

该测试用于确认正常调度入口能否返回后续机器故障研究需要的全部字段。

测试代码已经建立，但按照项目规则，本次没有运行 MATLAB。

## 5. 正常调度基线包含什么

`baseline` 结构包含：

| 字段 | 含义 | 后续用途 |
|---|---|---|
| `chrom` | 正常计划染色体 | 保留原始调度决策 |
| `machineTable` | 各机器加工时间表 | 判断故障机器上受影响的工序 |
| `AGVTable` | 各 AGV 运输时间表 | 判断需要冻结或重新安排的运输 |
| `makespan` | 正常计划最大完工时间 | 计算完工时间偏差 `tD` |
| `machineEnergy` | 机器能耗 | 保留原项目评价结果 |
| `agvEnergy` | AGV 能耗 | 保留 AGV 联动评价 |
| `totalEnergy` | 总能耗 | 比较调整前后的能耗 |
| `agvEGRecord` | AGV 电量变化 | 后续检查运输调整是否可行 |
| `agvChargeNum` | AGV 充电次数 | 保留充电约束信息 |
| `problem` | 工件、工序和机器数据 | 故障状态提取和重调度 |
| `machineData` | 距离和机器能耗数据 | 重新安排机器和运输 |
| `agvData` | AGV 参数 | 重新生成运输任务 |
| `energyConfig` | 电量与充电参数 | 维持原 AGV 约束 |

## 6. 这一步没有做什么

本步骤没有：

- 定义机器故障事件；
- 设置维修时间；
- 判断故障影响范围；
- 实现二叉树右移；
- 实现完全重调度；
- 修改 AGV 运输计划；
- 运行 INSGA-II 正式实验；
- 运行 MATLAB；
- 修改 `raw_code/`。

所以当前得到的是“故障前计划生成入口”，不是机器故障处理结果。

## 8. 这一步完成后带来了什么

后续机器故障模块不需要再理解整个 `dif_main.m`，只需要调用正常调度入口得到 `baseline`。

后续流程可以建立为：

```text
baseline = 正常调度基线
→ 输入故障事件
→ 根据 baseline 提取故障时刻状态
→ 生成右移方案
→ 生成完全重调度方案
→ 与 baseline 比较并选择
```

这使正常调度和机器故障处理形成明确边界。

## 9. 下一步

下一步原计划是执行 MATLAB 契约测试，验证正常调度入口能够真正生成 `baseline`。

### MATLAB 运行方式

运行测试前，MATLAB 的“当前文件夹”必须是本项目根目录，而不是原正常调度项目或其他目录。

先在 MATLAB 中确认：

```matlab
pwd
```

当前目录应当是你本地克隆或保存的 `DFJSP` 项目根目录，并且该目录下能够看到：

```text
README.md
tests/
scripts/
src/
raw_code/
```

然后运行：

```matlab
run(fullfile(pwd, 'tests', 'test_normal_schedule_contract.m'))
```

如果 MATLAB 当前目录不在项目根目录，`run('tests/test_normal_schedule_contract.m')` 会因为找不到相对路径而报告“RUN 需要有效的 MATLAB 脚本”。这不代表测试逻辑已经运行或失败。

测试通过后，才进入阶段 A 第 2 步：

> 定义“在某道工序完成时发生”的单机器故障事件。
