# 未覆盖场景补充计划

> 历史说明：本文原用于补齐 `C-S2` 和 `C-SEQ2`。这两个场景当前已经在阶段 C 总结和项目总收口文档中补齐并封版，因此本文保留为过程记录，不再作为当前待办清单。

## 1. 为什么还要补

本文最初用于说明主线已经覆盖了单机器故障、加工中故障、从头加工规则、
多机器同时故障和连续故障，但阶段 C 的最终矩阵中还要补两类补充场景：

| 场景 | 含义 | 当前状态 |
|---|---|---|
| `C-S2` | 多机器同时故障，故障前进度作废，从头加工 | 当前已完成 |
| `C-SEQ2` | 连续故障，后一故障发生时前一机器仍在维修 | 当前已完成 |

这两个场景是对当前结论边界的补充；当前它们已经完成，不再是待办项，而是
收口版证据的一部分。

## 2. C-S2 补充步骤

目标：

> 在同时故障场景下，将中断规则从 `resume_remaining` 扩展为
> `restart_from_zero`。

建议步骤：

1. 定义同时故障下的从头加工中断承诺；
2. 为每个故障中断工序记录损失加工段和完整重加工段；
3. 扩展同时故障局部右移，使其写入完整重加工段；
4. 扩展同时故障 AGV 影响分析；
5. 扩展同时故障 AGV 联动右移；
6. 扩展同时故障完全重调度冻结问题；
7. 扩展同时故障解码器，支持多个从头加工承诺；
8. 运行轻量搜索契约；
9. 建立正式搜索入口；
10. 执行组合选择和最终审计；
11. 纳入阶段 C 最终多随机种子矩阵。

完成标准：

- 每个中断工序故障前进度均不保留；
- 修复后按完整原加工时间重新加工；
- 损失加工段和完整重加工段均计入机器工作能耗；
- 维修区间不计入机器工作能耗；
- 局部右移和完全重调度均通过机器、工件、AGV、维修和能耗审计；
- `C-S2` 可进入最终多随机种子入口。

## 3. C-SEQ2 补充步骤

目标：

> 在连续故障中，允许后一故障发生时，前一故障机器仍处于维修不可用状态。

建议步骤：

1. 构造维修区间重叠的连续故障事件；
2. 在当前计划视图中保留尚未结束的历史维修区间；
3. 提取下一故障状态时，同时识别新故障和仍在维修的旧故障；
4. 合并历史不可用区间与新不可用区间；
5. 检查同一机器维修区间重叠/相接时的合并结果；
6. 传播新故障影响，同时保留历史影响；
7. 生成局部右移候选；
8. 建立完全重调度冻结问题；
9. 运行轻量搜索契约；
10. 执行正式搜索、组合选择和多随机种子审计。

完成标准：

- 后一故障处理时不回滚前一故障历史；
- 当前计划视图包含仍有效的历史维修约束；
- 同一机器多个维修区间规范化正确；
- 不同机器维修区间互不混淆；
- 局部右移和完全重调度均通过全时间轴审计；
- `C-SEQ2` 可进入最终多随机种子入口。
