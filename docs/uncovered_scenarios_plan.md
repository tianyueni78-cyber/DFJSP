# 未覆盖场景补充计划

## 1. 为什么还要补

当前主线已经覆盖了单机器故障、加工中故障、从头加工规则、多机器同时故障
和连续故障。但阶段 C 的最终矩阵中仍有两个场景没有实现：

| 场景 | 含义 | 当前状态 |
|---|---|---|
| `C-S2` | 多机器同时故障，故障前进度作废，从头加工 | 未实现 |
| `C-SEQ2` | 连续故障，后一故障发生时前一机器仍在维修 | 未实现 |

这两个场景是对当前结论边界的补充，不会推翻已有结果，但可以让“多机器
故障覆盖范围”更完整。

## 2. 优先级

建议先补 `C-S2`，再补 `C-SEQ2`。

原因：

1. `C-S2` 可以复用阶段 C 的同时故障框架和阶段 B-R 的从头加工规则；
2. `C-SEQ2` 涉及计划版本、历史维修区间、新维修区间重叠，复杂度更高；
3. 先完成 `C-S2`，可以先验证“多机器 + 从头加工”这一个变量；
4. 再进入 `C-SEQ2`，避免同时引入从头加工和维修重叠两个新变量。

## 3. C-S2 补充步骤

目标：

> 在同时故障场景下，将中断规则从 `resume_remaining` 扩展为
> `restart_from_zero`。

建议步骤：

1. 定义同时故障下的从头加工中断承诺；
2. 为每个故障中断工序记录损失加工段和完整重加工段；
3. 扩展同时故障局部右移，使其写入完整重加工段；
4. 扩展同时故障 AGV 影响分析；
5. 扩展同时故障 AGV 联动右移；
6. 扩展同时故障完全重调度冻结问题；
7. 扩展同时故障解码器，支持多个从头加工承诺；
8. 运行轻量搜索契约；
9. 建立正式搜索入口；
10. 执行组合选择和最终审计；
11. 纳入阶段 C 最终多随机种子矩阵。

完成标准：

- 每个中断工序故障前进度均不保留；
- 修复后按完整原加工时间重新加工；
- 损失加工段和完整重加工段均计入机器工作能耗；
- 维修区间不计入机器工作能耗；
- 局部右移和完全重调度均通过机器、工件、AGV、维修和能耗审计；
- `C-S2` 可进入最终多随机种子入口。

## 4. C-SEQ2 补充步骤

目标：

> 在连续故障中，允许后一故障发生时，前一故障机器仍处于维修不可用状态。

建议步骤：

1. 构造维修区间重叠的连续故障事件；
2. 在当前计划视图中保留尚未结束的历史维修区间；
3. 提取下一故障状态时，同时识别新故障和仍在维修的旧故障；
4. 合并历史不可用区间与新不可用区间；
5. 检查同一机器维修区间重叠/相接时的合并结果；
6. 传播新故障影响，同时保留历史影响；
7. 生成局部右移候选；
8. 建立完全重调度冻结问题；
9. 运行轻量搜索契约；
10. 执行正式搜索、组合选择和多随机种子审计。

完成标准：

- 后一故障处理时不回滚前一故障历史；
- 当前计划视图包含仍有效的历史维修约束；
- 同一机器多个维修区间规范化正确；
- 不同机器维修区间互不混淆；
- 局部右移和完全重调度均通过全时间轴审计；
- `C-SEQ2` 可进入最终多随机种子入口。
